# AJ Steinmetz — Academic Record Data

Single source of truth for publications, talks, teaching, employment, service, and other records of AJ Steinmetz. `build.py` renders them into documents in other repositories:

| Repository | Outputs |
|---|---|
| [cv-ajsteinmetz](https://github.com/ajsteinmetz/cv-ajsteinmetz) | `cv_ajsteinmetz.tex` / `.pdf` |
| [ajsteinmetz.github.io](https://github.com/ajsteinmetz/ajsteinmetz.github.io) | `cv.md`, `publications.md`, `talks.md`, `teaching.md`; Recent Publications block in `index.md` |
| [ajsteinmetz](https://github.com/ajsteinmetz/ajsteinmetz) | Code for Papers block in the profile `README.md` |

---

## Updating

1. Edit the relevant file in `data/` (one YAML file per data type; each file's header explains its fields).
2. Run the build from this directory. The consumer repos are expected next to this one (e.g. `../cv-ajsteinmetz`):

   ```bash
   pip install -r requirements.txt   # first time only
   python build.py --pdf
   ```

3. Review and commit the changes in this repo and in each consumer repo.

| Command | Effect |
|---|---|
| `python build.py` | Write every output |
| `python build.py --pdf` | ...and run each output's compile step (e.g. `pdflatex` for the CV) |
| `python build.py --check` | Report out-of-date outputs and exit 1; writes nothing |
| `python build.py --only cv-ajsteinmetz` | Build one consumer (repeatable) |
| `python build.py --repos DIR` | Look for consumer repos in `DIR` instead of this repo's parent |

**Generated files are overwritten on every build: edit `data/` or a consumer's `_build/templates/`, never the outputs.**

Style conventions (en dashes, HTML entities vs. LaTeX accent macros, `ACT\slash HEBUT`, bolding "Steinmetz, A.", identifier formatting, footnote lettering) are applied by the `Renderer` in `build.py`, so data files hold plain Unicode text with `*italic*` as the only markup, and every output formats records the same way.

## How consumers work

Each consumer repo listed in `targets.yml` owns its templates and says what to generate in `_build/`:

```
<consumer>/_build/
├─ build.yml           # manifest: which outputs to render
└─ templates/          # Jinja templates (delimiters: << expr >>, <% stmt %>, <# comment #>)
   └─ blocks/          # templates for marker blocks, named <block-name>.<ext>
```

`build.yml`:

```yaml
public: true                 # required; reserved for a future private-data overlay
outputs:
  - template: cv.tex         # relative to _build/templates/
    output: cv_ajsteinmetz.tex
    compile: pdflatex        # optional; runs (twice) with --pdf
  - output: index.md
    blocks: true             # refill marker blocks only
```

- **Full outputs** are rendered from `template` and overwritten. `.md`/`.html` outputs get a trailing "Generated by…" comment.
- **Block outputs** (`blocks: true`) stay hand-written except between markers, which are refilled from `_build/templates/blocks/<name>.<ext>`:
  - Markdown/HTML: `<!-- BEGIN GENERATED: name -->` … `<!-- END GENERATED: name -->`
  - LaTeX: `% BEGIN GENERATED: name` … `% END GENERATED: name`
- The renderer (`tex`, `md`, or `html`) is inferred from the output's extension; set `kind:` to override.
- Templates get the data files as variables (`publications`, `talks`, `profile`, ...), plus `pubs` (visible publications grouped by type), `pubs_all`, `awards_all` (visible grants and awards), `awards_by_type`, and the renderers `r` (output format) and `h` (HTML fragments).

### Adding a consumer (e.g., a grant or promotion package)

1. In the new repo, add `_build/build.yml` and `_build/templates/`.
2. Add the repo's folder name to `targets.yml`.
3. Run `python build.py --only <repo>` and review the output.

Only public records belong in `data/`. Private material (pending proposals, budgets, referee names) should stay hand-written in the private repo for now; the `public:` manifest key reserves room for a private-data overlay if that becomes worth building.
